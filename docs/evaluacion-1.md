# Evaluación Parcial 1 — Planificando un proyecto de software

Resumen operativo para el equipo. La rúbrica oficial vive en Canvas / maleta didáctica (no se sube a GitHub).

## Datos

| | |
|---|---|
| Semana | 5 (el caso se elige en la 4) |
| Tiempo | 5 horas, Sala de Proyectos |
| Equipo | 3 sugeridas; somos 4 → **todas hablan** en el oral |
| Peso | 30% del bloque de parciales (≈ 18% de la nota final del ramo) |

## Qué se entrega

1. **Informe grupal** (resumen ejecutivo), PDF, máximo **7 planas**
   - Arial o Times 12, interlineado 1.5, márgenes 2.5 cm, citas APA
2. **Pitch analógico** (pizarra, kraft, plumones), ~15 minutos
3. Preguntas **individuales** a cada integrante sobre **toda** la unidad

Dentro de la Eva 1: informe **30%** · oral **70%**.

## Los cuatro bloques del informe

1. Alcance, recursos, cronograma + contexto de la organización + plan con herramienta de industria
2. Factores ambientales y estándares, **impacto en este caso**
3. Estrategias de planificación e integración **contextualizadas** (predictivo / adaptativo / híbrido)
4. Herramientas usadas, **justificadas** (MS Project, Project Libre, Office 365, etc.)

## Seis preguntas del pitch (ensayar sin leer)

1. Contexto y necesidades de la organización
2. Cómo se determinaron alcance y recursos
3. Criterio técnico del cronograma (EDT → duraciones → CPM/PERT)
4. Beneficios de las estrategias de planificación e integración
5. Qué del contexto organizacional se incorporó
6. Qué herramientas y **por qué**

## Archivos de entrega en este repo

Carpeta `Eva 01/entrega/`:

- Cronograma / XML de Project o Project Libre
- Gantt o HTML de ruta crítica

El Word/PDF final del informe puede vivir aquí cuando esté listo (nombres claros: `informe-parcial-1.md` o `.pdf` **nuestro**, no la rúbrica de Duoc).
